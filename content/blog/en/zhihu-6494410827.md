## 1. Sensors and Odometry

The odometry part is also referred to as the front end of SLAM. It differs from traditional sensor-based localization and navigation; classical integrated systems like inertial/GNSS directly output signal data, which can be fed straight into the back end for optimization (filtering). In the emerging SLAM paradigm, sensors such as cameras and LiDAR that output spatial point information are more commonly used, requiring the front end to perform some information preprocessing.

In planning, common sensors include RGB cameras, depth cameras, LiDAR, TOF, and even some like thermal infrared cameras, millimeter-wave radar, and event cameras. Ultimately, they all aim to provide depth information about obstacles. Data from traditional cameras typically undergo feature point extraction to obtain sparse feature point clouds, which are used to derive feature landmarks for the back end's localization and mapping; LiDAR, on the other hand, directly outputs dense point clouds, which can be stitched together via registration algorithms.

In the front-end odometry, since we need to associate data from a few consecutive frames to extract motion information, we must model the sensor. Subsequently, the relationship between short-term motion and sensor information is modeled accordingly. For vision, this includes feature extraction and matching (for feature-point-based methods), optimization via multi-view geometry techniques like bundle adjustment, as well as alternatives such as optical flow and direct methods. For LiDAR, it involves registration, which is essentially a clustering and fitting problem.

## 2. Coupling of Localization and Mapping

The very existence of the SLAM field stems from the strong coupling between localization and mapping tasks. For mapping, accurate localization is essential to better stitch local maps into a global map. Conversely, a correct understanding of the surrounding environment enables better localization.

## 3. Map Representations

[https://zhuanlan.zhihu.com/p/259370498?utm_psn=1851452326918889472](https://zhuanlan.zhihu.com/p/259370498?utm_psn=1851452326918889472)

The two main issues with maps are data structures and information fusion within the map. This topic overlaps somewhat with computer graphics. The map representations commonly seen in planning include the following:

### 1. Occupancy Grid Map[\[1\]](#ref_1)

Arguably the simplest and most commonly used map, it also provides an intuitive way to demonstrate algorithm performance in teaching. The basic idea is to represent the map as a uniformly spaced, discrete binary field. The types of grid cells are:

- **Obstacle grid:** Fully occupied by obstacles, typically assigned a value of 1.
- **Free grid:** No obstacles within the cell, typically assigned a value of 0.
- **Mixed grid:** Partially occupied by obstacles; this can also be classified as an obstacle grid.

For fine resolution, such maps can use very high resolution, making them the densest. However, the dense subdivision consumes significant memory. Theoretically, memory of the corresponding map size should be pre-allocated in the program, but in practice, a rolling-window approach can be used to save memory. This is a structured mapping method, and we can directly query the grid type by coordinate indices.

![](/blog-assets/zhihu/6494410827/image-02.jpg)

2D grid map

![](/blog-assets/zhihu/6494410827/image-04.jpg)

2.5D grid map

These can be 2D, 3D, or 2.5D (adding height information to a planar grid without further subdividing the third dimension).

In practice, sensor measurement data inevitably contains noise and uncertainty, and the resulting map is accumulated over multiple measurements. Thus, our binary field is a binary random variable field. Based on current observations of the grid's state, we compute an approximate posterior estimate. This essentially employs Bayesian filtering. I believe anyone with a basic grasp of Bayesian methods can follow the derivation ()

![](/blog-assets/zhihu/6494410827/image-06.jpg)

We can set a threshold for the update to decide whether to flip the binary value of a grid cell. This filter algorithm is conveniently applicable when the sensor pose is known but the observations are noisy. Moreover, the algorithm only involves additions and subtractions, making it computationally efficient.

### 2. Octo Map[\[2\]](#ref_2)

Since occupancy grid maps require dense subdivision and thus consume a lot of memory, and in most scenarios the proportion of obstacles is relatively small, the obstacle-free regions need not be subdivided as finely. This motivated the introduction of the octree map.

This map is sparse yet structured. Unlike grid maps, we cannot query directly by coordinates; instead, we must recursively traverse the tree structure.

During construction, if a cell contains an obstacle, it is recursively subdivided until the smallest block containing the obstacle is reached, or the minimum resolution is hit. In other words, in the final subdivision, mixed cells theoretically do not exist. This creates a coarse-to-fine hierarchical structure.

### 3. Voxel Hashing[\[3\]](#ref_3) [\[4\]](#ref_4)

Storing voxels in a hash table is the sparsest map representation; it is also structured and cannot be directly indexed by coordinates.

The current grid's xyz coordinates or other information are mapped to a hash key, which is inserted into a lookup table. When querying, the same function is used to compute the key and retrieve the data.

Additionally, several voxels (e.g., 5×5) are grouped into a block. The hash table stores data by block; upon querying, the block is extracted first, followed by fine-grained access to individual voxels.

![](/blog-assets/zhihu/6494410827/image-10.jpg)

### 4. Point Cloud Map[\[5\]](#ref_5)

Point clouds are the raw measurement sets of the most basic sensors. For instance, visual sensors combined with visual SLAM yield sparse feature point clouds; single-line LiDAR scanning registers and accumulates successive scans to produce dense feature point clouds.

![](https://pica.zhimg.com/v2-8acef75fc5f15fcd19b27473f9147ede_r.jpg)

Points are unordered, and since traversal costs are prohibitive for indexing, using point clouds for motion planning requires additional techniques.

### 5. TSDF (Truncated Signed Distance Field) Map[\[6\]](#ref_6)

A distance field is established between the sensor and obstacles, representing the shortest distance from any point in space to the nearest obstacle. Values are positive between the sensor and obstacles and negative inside obstacles (indicating the nearest distance to safe space). This yields a signed distance field.

"Truncated" means we do not need to maintain the distance field for all grid points in the map—e.g., we ignore points outside the view frustum, and distances beyond a minimum distance \(d_{\text{min}}\) or maximum distance \(d_{\text{max}}\) are not tracked. Moreover, we do not retain history; instead, we perform frame-by-frame information fusion.

![](https://picx.zhimg.com/v2-a999402e24cb3836efff678dea557b93_r.jpg)

### 6. ESDF (Euclidean Signed Distance Field) Map

A signed distance field is built on top of a grid map using Euclidean distance.

![](/blog-assets/zhihu/6494410827/image-12.jpg)

Distance Transforms of Sampled Functions, PF Felzenszwalb

There are three classic frameworks:

(1) Incremental mapping on top of a grid map[\[7\]](#ref_7) [\[8\]](#ref_8)

In navigation, the local planning region is small; incrementally building an ESDF for the entire map has large memory overhead and is unnecessary. Although incremental methods are faster, they are less convenient to implement than batch mapping on a grid map, since we only plan over a small region.

(2) Incremental mapping on top of a TSDF

The difference from the truncated distance field lies in its global nature; before the advent of ESDF-free methods with non-truncated soft constraints, many approaches relied on this map to obtain gradient information.

(3) Batch mapping on top of a grid map[\[9\]](#ref_9)

Thus, we adopt a strategy of incremental updates for global mapping and batch updates for the local map to build the Euclidean signed distance field. For the local map, the complexity scales with the number of map nodes, computing the ESDF for each grid cell as quickly as possible. When the robot moves, the new region is refreshed, and the previous local map is discarded.

### 7. [Free-space Roadmap](https://zhida.zhihu.com/search?content_id=250321367&content_type=Article&match_order=1&q=%E5%AE%89%E5%85%A8%E7%A9%BA%E9%97%B4%E8%B7%AF%E7%BA%BF%E5%9B%BE&zhida_source=entity) [\[10\]](#ref_10)

A common approach is to randomly sample nodes in a [probabilistic roadmap](https://zhida.zhihu.com/search?content_id=250321367&content_type=Article&match_order=1&q=%E6%A6%82%E7%8E%87%E8%B7%AF%E7%BA%BF%E5%9B%BE&zhida_source=entity), then expand each node into a safe convex region and connect these convex polyhedra to form traversable areas. The reason for expanding into convex regions is primarily to formulate the subsequent trajectory optimization as a convex optimization problem.

### 8. [Voronoi Diagram Map](https://zhida.zhihu.com/search?content_id=250321367&content_type=Article&match_order=1&q=Voronoi%E5%9B%BE%E5%9C%B0%E5%9B%BE&zhida_source=entity) [\[11\]](#ref_11)

Voronoi [polygons](https://zhida.zhihu.com/search?content_id=250321367&content_type=Article&match_order=1&q=%E5%A4%9A%E8%BE%B9%E5%BD%A2&zhida_source=entity) are a common concept in computer graphics.

This approach efficiently leverages the data structure of ESDF maps to extract a skeleton. For large-scale mobile robot global path planning where the [topological](https://zhida.zhihu.com/search?content_id=250321367&content_type=Article&match_order=1&q=%E6%8B%93%E6%89%91&zhida_source=entity) structure of the path is of interest, planning can first be performed on such a [topological map](https://zhida.zhihu.com/search?content_id=250321367&content_type=Article&match_order=1&q=%E6%8B%93%E6%89%91%E5%9C%B0%E5%9B%BE&zhida_source=entity). Being highly sparse, search on this map consumes significantly fewer computational resources than on grid maps.

It is worth noting that the "map" or "mapping" in planning or exploration differs conceptually from mapping in SLAM. SLAM requires a high-precision, texture-rich map, whereas a map for planning—if as detailed as a SLAM map—would make real-time planning infeasible. In practice, coarser representations such as grid maps, which sufficiently capture obstacles in the environment, are used to obtain the basic depth information needed for planning. Additionally, some planning methods operate directly on raw sensor data (e.g., point clouds).
