## I. Overview

In kinodynamic path finding, the term "kinodynamic" is a portmanteau of "kinematic" and "dynamic," meaning that kinematic constraints (e.g., obstacle avoidance) and dynamic constraints (i.e., differential constraints such as limits on velocity, acceleration, and force magnitude) are considered jointly during robot motion. A kinodynamic solution should include a mapping from time to generalized forces or accelerations. [\[1\]](#ref_1)

As I mentioned in the first article of this series [\[2\]](#ref_2], planning is a coarse-to-fine process. The functions of upper and lower layers should not be rigid or fixed, nor should the two layers be completely decoupled.

In detail, on one hand, an "optimal" path that ignores dynamics entirely may be infeasible for the system, since it violates the system's differential constraints. Incorporating system dynamics constraints can relieve the optimization burden on the lower-level trajectory planner. On the other hand, lower-level optimization is often only a local optimization that seeks the nearest local optimum. However, paths that satisfy and do not satisfy dynamics constraints may belong to different homotopy classes, and it is almost impossible for lower-level optimization to cross different homotopy classes. This means that for common underactuated systems, a so-called "optimal" path that ignores dynamics may incur considerable extra cost.

For example:

![](https://picx.zhimg.com/v2-aa482f9b915da7da435d73566b475b1b_r.jpg)

In the figure above, if we ignore dynamics, the resulting path is the green line. But clearly, such a path is very jerky for a normal vehicle, since a car cannot move laterally. After backend optimization, it would generally incur greater cost (energy, time). The orange line, in contrast, is a path that considers dynamics constraints. Clearly, the two belong to different homotopy classes.

![](/blog-assets/zhihu/7223290479/image-02.jpg)

In the figure above, the red arrow indicates the UAV's current velocity; the solid purple line represents the path planning result, and the dashed purple line represents the result after optimizing the solid purple line; the solid green line represents the dynamics-aware path planning result, and the dashed green line is the result after optimizing the solid green line. The solid purple line, which only considers the shortest path, involves sharp turns and steering after optimization, and is actually less smooth than the dashed green line, with lower cost. Moreover, the two belong to different homotopy classes, so the solid purple line cannot be locally optimized into the one on the right.

## II. State Lattice Planning

### (1) Two Basic Ideas for Discretization

1. Basic idea

Discretize (including sampling) the state space while accounting for dynamics. In this way, performing path search in the discrete space yields a discrete path that satisfies dynamics.

There are then two approaches. One is to discretize in the control space: within a fixed time step, the discretized control space produces a finite (or countable) set of motion primitives via numerical integration. We call this **forward discretization**. The other is to discretize in the state space, and then from the current initial state, find a finite (or countable) set of motion primitives connecting to the discrete (terminal) state space. This process essentially solves a fixed-end optimal control problem (called a Boundary Value Problem, or BVP, in Professor Gao Fei's course). We call this **backward discretization**.

2. Pros and cons of the two approaches

Forward discretization is easy to implement: given an initial state x0, fix some control input u and time step T, and integrate forward. Numerical integration is simpler to solve than an optimal control problem (at least intuitively), which implies lower computational cost and allows for higher resolution in discretization. However, it is not task-oriented, meaning it does not directly consider that the essence of planning is to connect initial and terminal states. Thus, planning efficiency is lower (here "efficiency" refers not to algorithmic runtime efficiency, but to the efficiency of finding a sufficiently good plan among many discretized options).

In contrast, backward discretization is harder to implement: given an initial state x0 and a fixed terminal state xf, one computes u and T (sometimes T is also fixed to simplify the problem). It consumes more computational resources, but it is task-oriented, so planning efficiency is higher.

In summary, regardless of the discretization approach, the computational burden is significant. Online construction requires considerable computation, and even offline construction followed by online search takes substantial time. Therefore, state lattice planning is typically used to discretize only one or two layers, or we resort to hybrid A* or dynamics-based RRT*\* described later. These latter methods can essentially be viewed as pruned variants of state lattice search.

### (2) A High-Level View of Path Planning

In fact, the earlier search-based and sampling-based path planning methods correspond exactly to special cases of these two discretization approaches. Search-based planning discretizes the control space into simple four- or eight-connected moves, meaning the control inputs only allow motion in these directions, thereby constructing a graph. Sampling-based planning essentially performs random discretization of the state space.

Of course, we should not take this knowledge too rigidly; there is no need to think that control-space discretization must be uniform discretization to build a grid map, or that state-space discretization must be random sampling. These are merely **two different discretization philosophies for converting high-dimensional complex continuous state-space planning problems into graph-theoretic or graph-search problems**. I believe this is the most essential meaning of discretization, and it is also the reason why path planning is always based on discretization. In the future, I may also publish a dedicated series on the core problems or fundamental difficulties in planning, and discuss how current frameworks handle or attempt to solve them.

### (3) Forward Discretization

1. A uniform discretization example for a UAV [\[3\]](#ref_3)

![](/blog-assets/zhihu/7223290479/image-04.jpg)

For this UAV linear model, the state is $s=(x,y,z,\dot x,\dot y,\dot z)^{T}$ , and the control input is $u=(\ddot x,\ddot y,\ddot z)^{T}$ , taking the form of an integrator chain $\dot s=As+Bu$ , where the system matrix is a nilpotent matrix.

$$
A=\left(\begin{array}{}0&I_3&0&\cdots&0\\ 0&0&I_3&\cdots &0\\ \vdots&\vdots&\vdots&\ddots&\vdots\\ 0&\cdots&\cdots&0&I_3\\ 0&\cdots&\cdots&0&0\\ \end{array}\right) B=\left(\begin{array}{}0\\ 0\\ \vdots\\ 0\\ I_3\\ \end{array}\right)
$$

If acceleration is used as the control input, and we perform a "9-way discretization" from some initial velocity, we obtain the shape shown on the left in the figure below. If jerk is instead used as the control input, with a given initial velocity and initial acceleration, we obtain the right panel of the figure below. We can then continue to perform forward integration from different terminal states, and so on.

![](/blog-assets/zhihu/7223290479/image-06.jpg)

Comparison of acceleration vs. jerk as control input

$$
s(t)=exp(At)s_0+\int_{0}^{t}exp(A(t-\tau))Bd\tau u_{m}
$$

The nilpotency of $A$ makes the matrix exponential a polynomial matrix in t (closed-form solution), which further simplifies the integration. $u_m$ is the discretized control input.

### (5) Task-Oriented Comparison [\[6\]](#ref_6)

![](https://picx.zhimg.com/v2-c0bd4f065cee6bb92e7175feebe48ce3_r.jpg)

In the autonomous driving scenario comparison above, we can observe the inefficiency of forward discretization: because it is not goal-directed, many generated motion primitives are invalid and fail the collision-free condition. Backward discretization, by contrast, ensures that more practically useful motion primitives are generated.

![](/blog-assets/zhihu/7223290479/image-12.jpg)

Another issue is shown in the figure above. Forward discretization has relatively few degrees of freedom, since the control input and time step are fixed. The resulting set of motion primitives exhibits a strong tendency toward homogeneity, largely influenced by the initial state. This homogeneity is detrimental to obstacle avoidance in dynamic environments.

This leads to an important problem in forward-discretization research: the spread of the generated motion primitives should be as uniform as possible, so as to reduce the situation where excluding one primitive due to collision constraints also eliminates many others at the same time.

### (VI) Implementation Details

1. **Iterative Graph Construction with Heuristic Search**

We perform graph search after forward-discretized graph construction, but we do not add all discretized control inputs for every state to build the complete graph first—making it as complex as the nine-discrete or even twenty-five-discrete graph displayed (that graph is only for aesthetics)—and then run the search. Instead, with the aid of heuristics, we purposefully perform search and necessary graph construction simultaneously. This implies that we use heuristic search algorithms rather than systematic search algorithms like Dijkstra.

Moreover, the selection of terminal states in backward discretization is not arbitrary either; it is heuristically chosen based on the results of higher-level task decisions.

In the earlier discussion of search-based methods [\[7\]](#ref_7), to simplify the task, A* operates on a pre-built grid map with memory pre-allocated, allowing real-time updates of obstacle information observed around the robot into memory for continuous map fusion. However, for state-lattice planning, constructing the entire map online is costly. It is entirely feasible to build the map only where the search progresses—search where you build, build where you search. This effectively saves both computation time and memory.

Accordingly, there are corresponding heuristic functions. Essentially, a heuristic function estimates the remaining cost to the goal. In the earlier search-based path planning, heuristic selection was mostly a matter of "grid-walking" problems. In dynamics-based path planning, we similarly simplify the problem before estimating the remaining cost. There are generally two simplification approaches: ignoring obstacles or ignoring dynamics [\[8\]](#ref_8). Sometimes, the results of both simplifications are combined via weighting or by taking the max.

![](https://picx.zhimg.com/v2-3873bc84e38223a1637aab5db6c398bd_r.jpg)

The triangle indicates the heading direction. On the left, ignoring dynamics is more appropriate; on the right, ignoring obstacles is the better choice.

When ignoring obstacles, we solve a fixed-terminal optimal control problem to the goal state to obtain the heuristic function. When ignoring dynamics, we perform ordinary path planning—there is no need to run forward A* from every start; we can run a backward Dijkstra search, or approximately compute Euclidean distances between several nodes or from start to goal [\[9\]](#ref_9).

![](/blog-assets/zhihu/7223290479/image-14.jpg)

Clearly, using a more refined optimal control curve as the heuristic function yields better results than a coarse Euclidean distance.

2. **Fixed-Terminal Optimal Control Problem**

Since this series is not specifically dedicated to optimal control (also because I am lazy), I will not go into fine detail. It is worth mentioning that [\[10\]](#ref_10) addresses integral-chain systems (e.g., $(p,v,a)^T$ with control input being the higher-order derivative jerk, $j = \frac{da}{dt}$). If the cost function $J$ is set as the integral of the squared control input, then the solution to the optimal control problem—including the optimal trajectory and optimal control input—is a polynomial.

![](/blog-assets/zhihu/7223290479/image-16.jpg)

Proof that the optimal polynomial trajectory for a single-integrator double chain is a polynomial.

For such polynomials, once the initial and goal states are known (fixed-terminal conditions), the polynomial coefficients depend only on the time step $T$. We can arbitrarily choose $T$ first and compute the coefficients of the optimal solution polynomial. Furthermore, the cost function $J$ depends only on the optimal solution polynomial coefficients and $T$. Substituting the computed coefficients and taking the stationary point with respect to $T$ yields the optimal $T$.

If the goal state is only partially specified—for example, only the position $p$ is fixed—we can also use transversality conditions to solve the problem.

3. **Trajectory Library** [\[11\]](#ref_11)

![](https://pica.zhimg.com/v2-558e42907f2784478f6ec4773ce35176_r.jpg)

This is a commonly used concept in engineering, called by different names, but it generally refers to the collection of results from a single-layer state-lattice search. For a robot in a simple environment without many dead ends or corner cases, such local planning is sufficient and very easy to solve, greatly reducing computational burden. In use, we do not need to perform graph search—only trajectory selection. We can construct a simple multi-term cost function considering collision risk, information gain, comfort, energy consumption, and other factors to select among the trajectories in the current library.

4. **Planning in Other Coordinate Frames (Frenet–Serret Frame)** [\[12\]](#ref_12) [\[13\]](#ref_13) [\[14\]](#ref_14)

Structured environments such as roads often have lane markings, and we often wish to follow the lane. This requires transforming the Cartesian coordinate system into a moving Frenet frame decomposed along the lane's tangential and normal directions. In autonomous driving, planning can be decoupled longitudinally and laterally in the tangential and normal directions. Simply put, the trajectory can be parameterized as a quintic polynomial. Below, we take simple lateral and longitudinal planning as examples; longitudinal planning needs to consider many rules, such as stopping, lane changes, and car following, which are handled case by case.

## III. Hybrid A* [\[15\]](#ref_15) [\[16\]](#ref_16)

Hybrid A* was first proposed in the context of autonomous vehicle applications and is commonly used in automatic parking system design. The basic concept and framework combine forward discretization with A*. Hybrid A* still maintains a grid map like A*, and when expanding in the state graph, it prunes the results of the state-lattice search according to the grid map structure.

### (I) Algorithm Details

Compared with A*, there are several differences: the computation of the accumulated cost $g(n)$ and the heuristic cost $h(n)$ differs; the search for neighboring nodes is performed by discretizing in the control space and forward-integrating with different $u$; therefore, the state points are not necessarily at grid cell centers, so the state points must also be recorded and updated.

![](/blog-assets/zhihu/7223290479/image-20.jpg)

Using different $u$ generates many feasible local motion primitives. Each terminal node is checked: if it falls in an empty grid cell, it is saved; if not, it is compared with the cost of the existing node, and the one with lower cost is kept while updating the node. Only when another point in the same cell can generate a shorter path is the stored state point updated. In short, each grid cell always contains only one node.

### (II) Heuristic Functions

Regarding the heuristic function—the estimate of remaining cost—consider the Euclidean distance between the start and goal positions and the dynamics-only heuristic that ignores obstacles. In general, the dynamics-only heuristic that ignores obstacles is tighter and more likely to preserve optimality (Figures a, b). However, in complex scenarios with many dead ends, ignoring obstacles can lead to getting stuck in local minima or dead ends due to greediness (Figure c), degrading search efficiency. In such cases, too many nodes are expanded and the heuristic is too inefficient. Weighting the obstacle-ignoring heuristic and the dynamics-ignoring heuristic together can yield better results (Figure d).

![](/blog-assets/zhihu/7223290479/image-22.jpg)

### (III) Analytic Expansions

Also called the "one-shot heuristic," this refers to directly solving a fixed-terminal optimal control problem between a node in the search and the goal. If the solution happens to be collision-free and dynamically feasible, the planning can be terminated early. Hybrid A* lacks greediness toward the goal, which makes it somewhat inefficient. Analytic expansion provides exactly such a greedy mechanism.

![](https://picx.zhimg.com/v2-644aa86b3b04b41aa3c3ad0cb763530f_r.jpg)

According to Professor Fei Gao's engineering experience, this trick is quite useful. During the Hybrid A* search, with a certain probability, after a state is expanded, we can directly solve the optimal control problem to the goal. Since success is only probabilistic, this requires an engineering trade-off: performing analytic expansion on every new node would be too costly and unnecessary. We can design, for example, one analytic expansion every $n=20$ searches. The closer the search gets to the goal, the higher the success rate of analytic expansion, so $n$ can be reduced as we approach the goal boundary.

1. **Autonomous Vehicles** [\[17\]](#ref_17)

Hybrid A* was first proposed for autonomous vehicle applications and is also frequently used in automatic parking.

2. **Drones** [\[18\]](#ref_18) [\[19\]](#ref_19)

## IV. Kinodynamic RRT*

The general idea is the same as RRT*, with differences only in the details of several functions. When RRT* was first proposed, it was actually in the kinodynamic form; it was only later applied to path planning.

### (I) Sampling

First, in `Sample`, kinodynamic RRT* always samples in the full state space. Suppose the LTI system dynamics are

$$
\dot x = Ax(t) + Bu(t) + c
$$

.

### (II) Nearest Neighbor Selection

Second, in `Near`, the distance metric is based on the cost function between different state points under optimal control. Lower cost means closer distance. Additionally, note that this metric is generally not symmetric.

1. **Fixed Final State and Arrival Time**

For example, the cost function $c(u,\tau) = \int_{0}^{\tau}(1 + u^{T}(t)Ru(t))dt$ is a "time-energy" quadratic form. We only need the arrival time $\tau$ and the control law $u(t)$ to compute the above cost. When the final state $x_1$ and arrival time $\tau$ are fixed, the optimal control law can be derived from optimal control theory as

$$
u^{*}(t) = R^{-1}B^{T}\exp(A^{T}(\tau - t))G^{-1}(\tau)(x_1 - \bar{x}(\tau))
$$

where $G(t) = \int_{0}^{t}\exp(A(t - t'))BR^{-1}B^{T}\exp(A^{T}(t - t'))dt'$ is the weighted controllability Gramian matrix, which can be solved via the following Lyapunov equation: $\dot G(t) = AG(t) + G(t)A^{T} + BR^{-1}B^{T}, \quad G(0) = 0$;

The free state trajectory $\bar{x}(t) = \exp(At)x_0 + \int_{0}^{t}\exp(A(t - t'))c\,dt'$ is the solution to the autonomous equation $\dot x = Ax(t) + c, \; x(0) = x_0$.

2. **Fixed Final State, Free Arrival Time**

To find the optimal arrival time $\tau$, we substitute the optimal $u^{*}(t)$ into $c(u,\tau)$. The integral can be evaluated explicitly to obtain $c(\tau) = \tau + (x_1 - \bar{x}(\tau))^{T}G^{-1}(t)(x_1 - \bar{x}(\tau))$.

The optimal $\tau$ can be obtained by differentiation:

$$
\dot c(\tau) = 1 - 2(Ax_1 + c)^{T}d(\tau) - d^{T}(\tau)BR^{-1}B^{T}d(\tau) = 0
$$

where

$$
d(\tau) = G^{-1}(t)(x_1 - \bar{x}(\tau))
$$

. Of course, the cost function can have multiple local minima, but for a double integrator chain, it is a fourth-order polynomial. Once the optimal time is found, we can return to solving the fixed-final-state, fixed-arrival-time problem in item 1.

### (III) Parent Node Selection and Rewiring

We only need to compute the control law and cost from state points in the existing search tree to the sampled state, and select the one with the smallest cost that also satisfies state and control input constraints. If none exists, resample.

To improve computational efficiency, we do not need to solve optimal control problems from all state points in the search tree. We can set a cost tolerance $r$ and compute the forward and backward reachable sets of the sample point $x_{rand}$ (respectively, points reachable from $x_{rand}$ and points that can reach $x_{rand}$; since the metric is asymmetric, the two sets do not coincide).

From the cost function $c(\tau)$ defined earlier, when the initial state $x_0$, cost tolerance $r$, and arrival time $\tau$ are fixed, the forward reachable set of $x_0$ can be expressed as an ellipsoid:

$$
\{x_1 | \tau + (x_1 - \bar{x}(\tau))^{T}G^{-1}(t)(x_1 - \bar{x}(\tau)) < r\} = \{x_1 | (x_1 - \bar{x}(\tau))^{T}\frac{G^{-1}(t)}{r - \tau}(x_1 - \bar{x}(\tau)) < 1\} = \varepsilon(\bar{x}(\tau), G(t)(r - \tau))
$$

where $\varepsilon(x, M) = \{x' | (x' - x)^{T}M^{-1}(x' - x) < 1\}$. For different arrival times $\tau$, this is the envelope of a family of ellipsoids.

![](/blog-assets/zhihu/7223290479/image-30.jpg)

If we use a KD-tree to store nodes, we can further reduce computation, but then we need to compute a partition of the state space. To simplify, we discretize the time $\tau$, compute the axis-aligned bounding box of the ellipsoid family envelope, and update the maximum and minimum values of the axis-aligned bounding box along different dimensions:

$$
\prod_{k=1}^{n}\left[ \min_{0<\tau<r} (\bar{x}_{k}(\tau) - \sqrt{G_{k,k}(\tau)(r - \tau)}), \; \max_{0<\tau<r} (\bar{x}_{k}(\tau) + \sqrt{G_{k,k}(\tau)(r - \tau)})\right]
$$

The same applies to the backward reachable set.

Thus, we can select neighboring points $x_{near}$ within the backward reachable set of $x_{rand}$ and choose the parent node among them; compute the forward reachable set of $x_{rand}$ and solve the two-point boundary value optimal control problem for rewiring.

![](https://picx.zhimg.com/v2-411ed2cec510a9bfbecaa03e1398fb1f_r.jpg)
