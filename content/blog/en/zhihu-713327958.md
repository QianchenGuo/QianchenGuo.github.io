## 1. Overview

The core idea is to avoid explicitly representing the configuration space and its obstacle boundaries using various geometric representations. Instead, sampling is used to guide the exploration of the connectivity of the configuration space.

Incremental sampling and search involves generating random, non-repeating sample points in the environment to guide a complex search tree as it grows, covering an increasingly large area. We hope that as the number of samples increases, the quality of the shortest path obtained in the generated tree improves. This is therefore a method that is independent of any specific geometric model, discretizing the configuration space through random incremental or batch sampling. Such algorithms solve problems with numerous geometric primitives that explicit representation methods for configuration-space obstacles cannot address. Compared with search-based methods, sampling-based methods are especially suitable for complex spaces and high-dimensional environments.

This class of algorithms shifts the fundamental combinatorial complexity into the collision detection module, which can be designed according to the specific application. It also sacrifices algorithmic completeness, settling instead for resolution completeness or probabilistic completeness, thereby circumventing the fundamental difficulties to some extent.

Details of sampling theory and collision detection modules will not be elaborated here; time permitting, they may be added as supplementary content in this series. The main content of this article is the framework of incremental sampling and search algorithms, and system dynamics models will not be introduced. Path planning considering system dynamics will be covered in the next article.

Sampling-based planning algorithms are divided into two phases: the learning phase (building the graph structure) and the query phase (graph search). We hope that during the learning phase we can search the connectivity of the configuration space and cover it. The learning phase can be further divided into two major tasks: exploration and exploitation. Exploration means seeking new information and extracting topological information from the space, which requires better sampling strategies; exploitation means using known information to improve solution quality, tree growth, and modify the graph structure, which requires better use of information. The differences between different types of sampling-based planning algorithms mainly lie in these two tasks.

## 2. Probabilistic Roadmap (PRM, 1996, TRA)[\[1\]](#ref_1)

### (1) Algorithm Introduction

In the learning phase, there is only exploration and no exploitation, mainly involving the following two operations:

1. Sampling: can be uniform sampling or biased sampling to improve efficiency;

2. Connecting sample points: we connect all sample points, where sample points that are too far apart need not be connected, and collision detection is performed to remove colliding connections.

After the learning phase is completed, we obtain a topological graph that extracts connectivity information. This graph structure can be viewed as a simplified version of a grid map, since the connectivity of the space is represented using local collision-free paths and relatively few nodes. Next comes the query phase, which performs graph search on the known topological graph. The graph search algorithm is the same as in the previous section.

### (2) Characteristics

The advantage of this method is that in static environments, the generated topological graph can be reused multiple times, i.e., it solves multi-query problems. After relaxing completeness to probabilistic completeness, there is no need to search the entire configuration space; instead, spatial topological features are extracted. This is especially efficient in high-dimensional, complex, and large-scale environments.

The disadvantage of this method is that it does not consider the robot's dynamic constraints and only performs path planning. In many cases, we care more about feasible solutions and do not need to solve multi-query problems. In such cases, this method does not specifically address path planning problems, as a great deal of effort is spent in the learning phase extracting the topology of the entire space, making it inefficient. Moreover, for dynamic environments, it is more important to specifically address path generation rather than focusing too much on the topology of the entire space.

### (3) Lazy Collision Detection

In sampling-based methods, especially in complex high-dimensional environments, the collision detection module consumes a significant amount of time, for example, when state queries are required. We can perform only necessary collision detection: in the learning phase, only consider connection distances to generate the topological graph, and then perform collision detection in the query phase. If a collision is found on the search path, the corresponding edge is removed, and a new graph search is performed on the adjacent nodes of the removed edge to find a collision-free path.

## 3. Rapidly-exploring Random Tree (RRT, 1998)[\[2\]](#ref_2) [\[3\]](#ref_3) [\[4\]](#ref_4)

### (1) Algorithm Introduction

Interestingly, RRT was originally used for dynamics-based path planning, and it was only later discovered that it performs even better in path planning. Compared with PRM, which directly explores the topological properties of the entire space, RRT adopts incremental exploration without an exploitation stage, extending samples while maintaining the shortest path found so far, making it much more efficient than PRM.

The search tree is built incrementally, generating the tree while maintaining the path. Once the goal point is added to the tree (or enters a certain neighborhood of the goal), tracing back in the reverse direction yields the path. Each branch of the tree has the same length. The procedure is to perform random sampling x\_rand, then find the nearest point x\_near in the tree, connect the two points, perform collision detection, and if it passes, add x\_new.

![](/blog-assets/zhihu/713327958/image-02.jpg)

The specific algorithm flow is shown in the figure below. There are several key modules that can be custom-designed: the sample function, the near function for finding nearest neighbors, the steer function for connection, and the collision detection module.

![](https://pica.zhimg.com/v2-1c92422177b336da77cb5dc2ca9fdbc4_r.jpg)

Algorithm Flow

### (2) Characteristics

The advantage of RRT is that, compared with PRM, it focuses more on our goal of generating collision-free paths. It is easy to implement and generally fast.

One might expect that RRT could obtain the optimal path by reducing the sampling step size and increasing the number of samples, but it has been proven that RRT does not possess asymptotic optimality. This is easy to understand, since the tree grows in straight lines and is also built from random samples; the search stops as soon as the goal is reached, so it cannot possibly be optimal. Furthermore, when facing the narrow passage problem, tree growth slows down because the probability of samples falling into the narrow passage is low, causing the tree to expand predominantly on one side. This means we can improve the RRT algorithm, and the room for improvement lies in the key modules mentioned above.

### (3) Implementation Details

1. KD-tree[\[5\]](#ref_5)

The RRT algorithm requires finding nearest neighbors, which brings us to a classic example of using data structures to reduce algorithmic complexity. A KD-tree reduces the search over all points in space, which is on the order of N, to a search over the tree depth, which is on the order of logN. Other techniques include spatial grids and hill climbing.[\[6\]](#ref_6)

2. Bidirectional RRT

Two search trees grow simultaneously from the initial point and the goal point until the two trees can connect to each other and a feasible path is found. This technique helps with the narrow passage problem, especially when either the initial point or the goal point lies within a narrow passage. However, it is of less help when neither lies within a narrow passage; the mainstream approach to narrow passages still relies on improving the sampling strategy.

## 4. RRT\* (2011, IJRR)[\[7\]](#ref_7)

### (1) Algorithm Introduction

RRT\* has not only exploration but also exploitation, implemented through parent node selection and local reconnection.

![](/blog-assets/zhihu/713327958/image-06.jpg)

Algorithm Flow

In RRT\*, x\_new is obtained in the same way as in RRT, but instead of immediately connecting x\_new to its nearest neighbor, a nearby region is searched to find a set of x\_near nodes, denoted as the set X\_near, corresponding to the NearC module in the algorithm flow above. When the tree expands, parent node selection (ChooseParent) is performed. The criterion for parent node selection is to compute which path from the initial point through each node in X\_near to x\_new has the minimum cost.

![](/blog-assets/zhihu/713327958/image-08.jpg)

After connecting x\_min and x\_new, the algorithm continues to examine the elements xi in X\_near\\x\_min, checking whether their incurred cost can be updated via a path through x\_new. If the incurred cost from the initial point through x\_new to x\_i is smaller than the original cost, the parent of x\_i is changed to x\_new. Compared with RRT, RRT\* re-evaluates the surrounding tree after each sample, determining whether a better path can be obtained through the new point and performing local reconnection through this rewiring operation, which makes it asymptotically optimal. This is essentially an ongoing process of tree optimization and pruning. Compared with RRT, after generating a feasible path, RRT\* can continue sampling and continuously optimize the tree.

![](/blog-assets/zhihu/713327958/image-10.jpg)

The figure below clearly demonstrates the improvement of RRT\* over RRT in terms of path cost, as well as the process of (probabilistic) asymptotic optimality:

![](https://pica.zhimg.com/v2-ebd85978b9be6c50b2956f54632cd3ba_r.jpg)

It can be observed that RRT\* continuously improves the path, giving points across the global range a strong outward-expanding directionality.

![](https://pica.zhimg.com/v2-4794a5048a7a4a7b6a7ddfeff5351292_r.jpg)

### (2) RRT\* and Dynamic Programming

In parent node selection and local reconnection (pruning optimization), the idea of dynamic programming is implicitly embedded, namely that local optimality leads to global optimality. Here, the optimal substructure is the optimal subpath within the neighborhood selected in NearC. This is also the key reason why RRT\*, as sampling increases, achieves not only probabilistic completeness but also asymptotic optimality.

It is worth noting, however, that compared with ordinary dynamic programming, sampling-based path planning discretizes the state space rather than the action space, and there is no concept of action u. The resulting graph is naturally undirected, and therefore has no notion of hierarchy, making it impossible to distinguish whether cycles exist. That is, in sampling-based path planning, the parent–child relationship between nodes can only be established through range search or k-NN nearest-neighbor search. This means that, unlike ordinary dynamic programming, one cannot use a single recursion to compute the optimal step at each stage. Therefore, one can only pursue asymptotic optimality in a probabilistic sense over multiple steps.

### (3) Neighborhood Range

Regarding the search range of the NearC module[\[8\]](#ref_8), the original 2011 paper proposed: $range=min \{ \gamma(  {log(card(V) )\over card(V)}  )^ {1\over d},\eta \}$

where η is the step size (branch length), d is the dimension of the state space, and to guarantee asymptotic optimality, γ satisfies

$$
\gamma >(2(1+{1\over d}))^{1\over d}({\mu(X_{free})\over\xi_d})^{1\over d}
$$

where μ is the measure, X\_free is the obstacle-free space, and ξ\_d is the volume of the unit ball in d-dimensional space. Empirically, for low-dimensional planning such as d = 2, 3, setting the search range slightly larger than the step size η suffices. In addition, in engineering practice, there is usually not enough time to wait for convergence to near-global optimality.

### (4) Anytime-RRT\*

After completing path planning, the robot needs to perform trajectory tracking. Anytime-RRT\* means that while the robot moves along the trajectory, it must still build the search tree in real time and update the path planning results. Continuous replanning allows the robot to adapt better to dynamic environments. The essence of real-time performance is to find a feasible solution as quickly as possible, then improve it as time progresses.

### (5) Over-Exploitation and Under-Exploitation

In RRT\*, there is an over-exploitation problem. Over-exploitation reconnects many nodes that have no potential, which can be illustrated by the following diagram. Suppose a feasible path with cost c\* already exists, and we find x\_new and parent node root. Rewiring node 1 is irrelevant to the existing path—for node 1, if the incurred cost g plus the heuristic function h exceeds c\*, then rewiring it offers no benefit to improving the existing solution.

![](/blog-assets/zhihu/713327958/image-12.jpg)

There is also an under-exploitation problem: rewiring only occurs when a new node is added to the search tree, and only in the neighborhood of that new node. RRT\* cannot guarantee that intermediate iterations produce optimal transition paths—it only guarantees local optimality in the neighborhood of the newly added node. As mentioned in Section (2), this is why, compared to DP's per-step optimality, RRT\* can only achieve asymptotic optimality through multiple steps. This can be illustrated by the following diagram:

![](/blog-assets/zhihu/713327958/image-14.jpg)

For the new node, a parent node 2 is found, and when rewiring node 3, nodes 1 and 4 should also be queried for rewiring. For RRT\*, the result may be as shown in the middle figure. However, we find in the lower figure that after node 3 changes its parent from 4 to new, the incurred cost decreases, and among 3's neighbors, node 5 can also lower its incurred cost by changing its parent from 4 to 3. Nodes like 5 that are overlooked due to under-exploitation are not few in number.

## V. Other Methods

### (1) RRT# (2013, ICRA) [\[9\]](#ref_9)

Since RRT\* has issues with the exploitation strategy during the learning phase, RRT# changes the exploitation strategy. As can be seen from the figure, RRT# exploits better near the goal point while preventing over-exploitation far from it, yielding some improvement over RRT\*.

![](/blog-assets/zhihu/713327958/image-16.jpg)

RRT\* guarantees that nodes throughout the entire search tree have reasonably good parent connections, whereas RRT# only cares about those near the goal.

![](https://pica.zhimg.com/v2-5cce0a21c8d03bea32da3f6537ab274a_r.jpg)

### (2) Informed RRT\* (2014, IROS) [\[10\]](#ref_10)

1. Algorithm Introduction

RRT\* samples uniformly across the entire space, and after finding a suboptimal feasible path, it continues global sampling and optimization. Informed RRT\* follows the principle that the optimal path must lie near the already-found suboptimal feasible path, so it always samples around the suboptimal feasible path found by RRT\*. The key insight is to improve sampling by estimating an omniscient set, focusing on the optimization process after obtaining a feasible solution. The omniscient set is the set in which sampling truly improves the solution, and it can be estimated via bounding box heuristics, path heuristics, L2 heuristics, etc.

The bounding box has upper and lower bounds in each dimension; path heuristics mean sampling around the current feasible solution; L2 heuristics constructs an ellipse, as follows:

After RRT\* generates a suboptimal feasible path, an ellipse is constructed with the start and goal points as foci and the path length as the major axis (the sum of distances to the two foci). Sampling is then performed only within this ellipse. As sampling inside the ellipse proceeds, the path length is continually optimized and the major axis shrinks. The ellipse continuously shrinks while approaching the theoretically optimal path, and the rate of convergence accelerates. Implementation: one can apply standard sampling algorithms, sampling uniformly in the unit circle and then applying an affine transformation. This of course depends on the form of the state space—when distances between two points are expressed using different norms, the corresponding different form of "ellipse" (i.e., the interior of a positive definite quadratic form) must be used.

![](/blog-assets/zhihu/713327958/image-18.jpg)

It can very quickly approach the shortest straight-line segment.

2. Performance Evaluation

For heuristic methods, define the omniscient set $X_f$ and the heuristic set $\hat{X_f}$ estimating the omniscient set. Precision is $precision={ \mu(X_f\cap\hat{X_f}) \over \mu (\hat{X_f})}$, and recall is $recall={ \mu(X_f\cap\hat{X_f}) \over \mu ({X_f})}$, where $\mu$ is a measure, used to evaluate the performance of different heuristic sets.

![](/blog-assets/zhihu/713327958/image-20.jpg)

Path heuristics have low recall, while bounding box heuristics tend to yield low precision because the bounding box is often set conservatively. L2 heuristics tend to achieve both high precision and high recall.

The following compares direct sampling in x\_PHS versus sampling in the rectangle x\_rect (direct sampling) but rejecting samples not in x\_PHS (rejection sampling) (middle figure: y-axis is rejection sampling precision; right figure: y-axis is 

$$
log({time\over sample})
$$

 ).

![](/blog-assets/zhihu/713327958/image-22.jpg)

The middle figure shows that the proportion of rejected samples falling into x\_PHS (precision) drops rapidly as the dimensionality of the state space increases, illustrating the sparsity of high-dimensional spaces and the importance of high precision. The right figure shows how the time magnitude required to sample a useful point in the heuristic set via direct versus rejection sampling changes with dimension; rejection sampling's time complexity also grows rapidly.

3. Characteristics

Compared to the non-informed version, Informed RRT\* requires an order of magnitude fewer iterations, while computational cost does not actually increase significantly.

Informed sampling algorithms can find the optimal path faster than globally sampling RRT in certain special scenarios (e.g., when the shortest path passes through a narrow passage where sampling probability is very low and the tree must be guided to grow). Because informed sampling increases the sampling probability in narrow regions. However, one must note that we rely on the principle that the optimal path already lies near the suboptimal feasible path. If this principle does not hold, the downside of the heuristic is falling into local minima.

Additionally, Informed RRT\* can be combined with the RRT# strategy to further improve the efficiency of the exploitation process.

### (3) GuILD (2021, arXiv) [\[11\]](#ref_11)

The informed sampling process can suffer from the following problem: in the environment shown below, the feasible solution initially sampled is very likely not in the narrow passage but rather in open areas with a highly tortuous path, resulting in a large heuristic set. Shrinking the heuristic set relies on improvements to the current feasible solution (cost reduction), but in this situation it is very difficult to improve the existing solution. This is called a pathological heuristic set.

![](https://picx.zhimg.com/v2-89224dee998c672ecd70e9e31b163f8f_r.jpg)

Red indicates a feasible solution that may be initially sampled; green indicates the optimal solution.

GuILD stands for Guided Incremental Local Densification. As the name suggests, we guide sampling to densify locally and incrementally. We can find a beacon point on the existing search tree (such as b in the figure below), then construct two local subsets: the "start-beacon set" and the "beacon-goal set," both using L2 heuristics with foci at (start, beacon) and (beacon, goal), respectively. Let the beacon's incurred cost along the search tree be g(b), and the current best feasible solution cost be c(ξ). These two sets must be subsets of the heuristic set (the outer large ellipse in the figure below), which provides an upper bound on their measures.

![](/blog-assets/zhihu/713327958/image-24.jpg)

GuILD mainly addresses two problems: the pathological case where the heuristic set is too large when a narrow passage exists, and the problem that when the current feasible solution does not improve much, the heuristic set cannot change significantly—even if the feasible solution cannot be updated promptly, local subsets can still be updated when other nodes are updated.

![](https://pica.zhimg.com/v2-4a9bcf954e3bec1c63984c44e99c4486_r.jpg)

Comparison of sampling effects in the heuristic set versus local subsets

![](/blog-assets/zhihu/713327958/image-26.jpg)

In the scenario above, the heuristic can no longer shrink, but GuILD fully exploits the improvement in the incurred cost from the start to the beacon. The "start-beacon set" shrinks rapidly as the beacon's incurred cost decreases (b–c); as g(b) decreases, c(ξ)-g(b) increases, and the "beacon-goal set" correspondingly expands. With the beacon as an intermediary, sampling in the two subsets trades off, and as long as the beacon is chosen well, the narrow passage can be traversed.

### (4) Cross-Entropy Path Planning

This differs significantly from RRT: the tree is not explicitly constructed. It is also an improvement to the sampling strategy. After generating an initial path with any method, a multi-Gaussian model is constructed at each node with the node as the mean and a specified variance. Then, guided by the multi-Gaussian model, many paths are sampled, and the mean is taken at each Gaussian node group across all paths to obtain a new set of nodes. This multi-Gaussian construction and optimization process is then repeated.

## VI. Implementation Details

### (1) Some Sampling Techniques

1. **Biased sampling**: Bias sampling toward the goal node, and with a certain probability, the goal point itself can be used as a sample point.
2. **Sampling rejection**: Certain samples can be rejected. When a feasible solution exists, record its cost c\*, design a feasible heuristic function h, and if a sample point has incurred cost g satisfying g+h > c\*, discard the sample.
3. **Branch-and-bound (pruning)**: During iteration, if a feasible solution with cost c\* already exists and some point on the existing search tree satisfies g+h > c\*, then the entire subtree below that node should be removed to avoid adding unnecessary complexity when performing Near in subsequent sampling. Of course, such algorithms are approximate and cannot guarantee optimality, because points in the pruned subtree might find better solutions through rewiring from other nodes—there is a trade-off here.
4. **Graph sparsity**: Discretize the space into a grid at a certain resolution, keeping only one sample point per cell. This yields fewer nodes, a simpler structure, and a sparser tree, though it also introduces suboptimality—only resolution-optimality in a probabilistic sense can be guaranteed.
5. **Dual-tree or multi-tree algorithms**.
6. There are also various choices of sampling strategy: deterministic vs. random sampling, batch vs. incremental sampling, informed sampling, and learning-based sampling (continuously learning and training in a given environment to extract environmental features so that sampling lands more effectively near the optimal solution).

### (2) Techniques for Nearest-Neighbor Search, Parent Finding, and Local Rewiring

1. **Nearest-neighbor search**: k-nearest or nearest-neighbor search can be performed; a kd-tree can be used for approximate nearest-neighbor search, and different k values can be used for different dimensions.
2. **Lazy collision checking**: When finding a parent or performing local rewiring, sort neighbors by potential incurred cost and perform collision checking in that order, stopping once a collision-free edge is found—similar to the lazy collision-checking philosophy.
3. **Conditional rewiring**: Since finding parents or rewiring incurs extra cost, one can first use RRT to find a feasible solution and then use RRT\* to improve it.
4. **Data reuse**: Many repeatedly computed quantities in code can be reused. For example, collision-check results between the same pair of nodes can be stored and reused when finding parents and during rewiring.
5. **Exploration–exploitation hybrid techniques**: Introduce local optimization into the tree-growing and graph-construction process, increasing attention to local solution quality.

It integrates well with MoveIt [\[20\]](#ref_20) and has strong applications in ROS. OMPL and MoveIt are used most often with robotic arms, and less with mobile robots—especially ground mobile robots—though a mobile robot can also be viewed as a manipulator with few joint degrees of freedom; the methods are analogous.
