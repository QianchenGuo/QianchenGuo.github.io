## 一、[隐式多线程](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E9%9A%90%E5%BC%8F%E5%A4%9A%E7%BA%BF%E7%A8%8B&zhida_source=entity)CPU

**CPU 端自动多线程**。优点是最省事，缺点是只能加速 MATLAB [内置函数](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%86%85%E7%BD%AE%E5%87%BD%E6%95%B0&zhida_source=entity)支持的部分，对你自己写的大量 `for` 循环帮助有限。[MathWorks](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=MathWorks&zhida_source=entity) 的并行计算选择指南也把“[向量化代码](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%90%91%E9%87%8F%E5%8C%96%E4%BB%A3%E7%A0%81&zhida_source=entity)”和“使用 MathWorks 产品中的自动并行支持”列为加速计算的基础方案。

### 1\. [向量化计算](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%90%91%E9%87%8F%E5%8C%96%E8%AE%A1%E7%AE%97&zhida_source=entity)：最基础也最重要的“隐式并行”

MATLAB 最擅长的是数组和[矩阵运算](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E7%9F%A9%E9%98%B5%E8%BF%90%E7%AE%97&zhida_source=entity)。很多时候，所谓“并行加速”的第一步不是立刻写 `parfor` 或上 GPU，而是把逐元素、逐样本、逐列的 `for` 循环改写成[矩阵表达式](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E7%9F%A9%E9%98%B5%E8%A1%A8%E8%BE%BE%E5%BC%8F&zhida_source=entity)。向量化后，MATLAB 底层可以调用经过优化的数值库，很多[线性代数](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E7%BA%BF%E6%80%A7%E4%BB%A3%E6%95%B0&zhida_source=entity)操作会自动利用多线程 CPU。

例如，低效写法是：

```text
N = size(X,2);
y = zeros(1,N);

for i = 1:N
    y(i) = sum(X(:,i).^2);
end
```

向量化写法是：

```text
y = sum(X.^2, 1);
```

向量化的优点是代码短、通常很快、不需要 [Parallel Computing Toolbox](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=Parallel+Computing+Toolbox&zhida_source=entity)，也不需要手动管理 worker。缺点是并不是所有问题都容易向量化，尤其是每次循环里有复杂逻辑、文件读写、仿真调用、条件分支很多时，向量化会变得困难。

在 MATLAB 里，向量化通常是所有并行手段之前的第一步，因为它同时有利于 CPU 多线程、GPU、[distributed arrays](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=distributed+arrays&zhida_source=entity) 等后续加速方式。

### 2\. MATLAB 内置函数的自动多线程

很多 MATLAB 内置函数本身已经是多线程的，比如[矩阵乘法](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E7%9F%A9%E9%98%B5%E4%B9%98%E6%B3%95&zhida_source=entity)、矩阵分解、[FFT](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=FFT&zhida_source=entity)、部分统计函数和[图像处理](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%9B%BE%E5%83%8F%E5%A4%84%E7%90%86&zhida_source=entity)函数等。用户写的代码表面上是单行，但底层可能已经调用多个 CPU 核心。

典型例子：

```text
C = A * B;
[V,D] = eig(A);
R = chol(A);
Y = fft(X);
```

这种方式的特点是**不需要你显式写[并行代码](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%B9%B6%E8%A1%8C%E4%BB%A3%E7%A0%81&zhida_source=entity)**。只要你的计算落在 MATLAB 高性能内置函数上，就可能自动吃到多核 CPU 的收益。

它的缺点也很明显：如果你的代码大量是自定义 `for` 循环、逐样本仿真、复杂 if-else 逻辑，那么 MATLAB 不会自动把这些循环拆到多个 CPU 核心上。此时就需要 `parfor`、`parfeval` 或其他显式[并行方式](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%B9%B6%E8%A1%8C%E6%96%B9%E5%BC%8F&zhida_source=entity)。

## 二、CPU 显式多worker并行

需要并行计算toolbox。本质上是把任务分给多个 MATLAB worker 执行。worker 可以是在你本机上的多个进程/线程，也可以在集群上。MathWorks 用户指南里说，MATLAB workers 是在后台运行、没有图形界面的 MATLAB computational engines，可以把任务分给这些 workers 并行执行；本地 workers 可以利用桌面多核 CPU，也可以扩展到集群。

### 1\. `parfor`：CPU[循环级并行](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%BE%AA%E7%8E%AF%E7%BA%A7%E5%B9%B6%E8%A1%8C&zhida_source=entity)

`parfor` 是 MATLAB 里最常用的 CPU 并行方式。它把普通 `for` 循环中彼此独立的[迭代](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E8%BF%AD%E4%BB%A3&zhida_source=entity)分发给多个 worker 同时执行。MathWorks 文档也明确说明，`parfor` 适合迭代次数很多、单次迭代较慢、并且各迭代相互独立的循环。

普通写法：

```text
for i = 1:N
    y(i) = expensiveFunction(x(i));
end
```

并行写法：

```text
parpool("local", 8)

parfor i = 1:N
    y(i) = expensiveFunction(x(i));
end
```

`parfor` 适合这类场景：

```text
parfor i = 1:N
    result(i) = runSimulation(param(i));
end
```

比如大量独立仿真、多[参数扫描](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%8F%82%E6%95%B0%E6%89%AB%E6%8F%8F&zhida_source=entity)、多随机种子实验、每个样本单独调用一个[耗时函数](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E8%80%97%E6%97%B6%E5%87%BD%E6%95%B0&zhida_source=entity)等。

`parfor` 的优势是改造成本较低，尤其是已有 `for` 循环时，经常只需要把 `for` 改成 `parfor` 并调整变量写法。缺点是它有调度开销，如果每次循环只耗时几毫秒甚至更少，`parfor` 可能反而更慢；另外，循环之间必须基本独立，不能有复杂的迭代依赖。

### 2\. `parfeval`：CPU 任务级[异步并行](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%BC%82%E6%AD%A5%E5%B9%B6%E8%A1%8C&zhida_source=entity)

`parfeval` 是异步并行。它不是像 `parfor` 那样“大家一起执行一个循环，然后等待全部完成”，而是把某个函数调用提交给 worker 后，主 MATLAB 会话可以继续执行其他代码，之后再用 `fetchOutputs` 取回结果。MathWorks 将 `parfeval` 与 `parfor`、`[spmd](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=spmd&zhida_source=entity)` 作为不同[并行编程模型](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%B9%B6%E8%A1%8C%E7%BC%96%E7%A8%8B%E6%A8%A1%E5%9E%8B&zhida_source=entity)进行区分。

基本形式：

```text
parpool("local", 4)

f1 = parfeval(@myFunction, 1, input1);
f2 = parfeval(@myFunction, 1, input2);

% 主线程可以继续做别的事情

out1 = fetchOutputs(f1);
out2 = fetchOutputs(f2);
```

它适合：

```text
futures = parallel.FevalFuture.empty(N,0);

for i = 1:N
    futures(i) = parfeval(@runOneExperiment, 1, configs{i});
end

for i = 1:N
    [idx, value] = fetchNext(futures);
    fprintf("Task %d finished\n", idx);
end
```

`parfeval` 的优势是灵活，适合任务耗时不均匀、想边运行边处理结果、想后台跑多个实验的情况。缺点是代码组织比 `parfor` 复杂一些，而且如果任务之间需要频繁通信，它并不合适。

| 对比项 | parfor | parfeval |
| --- | --- | --- |
| 执行方式 | [并行循环](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%B9%B6%E8%A1%8C%E5%BE%AA%E7%8E%AF&zhida_source=entity)，通常等待整体完成 | [异步任务](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%BC%82%E6%AD%A5%E4%BB%BB%E5%8A%A1&zhida_source=entity)，可边运行边取结果 |
| 适合结构 | 大量同质循环 | 多个异质任务、耗时不均任务 |
| 代码复杂度 | 较低 | 较高 |
| 结果获取 | 循环结束后统一得到 | fetchNext / fetchOutputs |
| 典型用途 | 参数扫描、独立样本评价 | 后台实验、[多任务调度](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%A4%9A%E4%BB%BB%E5%8A%A1%E8%B0%83%E5%BA%A6&zhida_source=entity)、异步 UI 更新 |

parfor 更像“把一个大循环[并行化](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%B9%B6%E8%A1%8C%E5%8C%96&zhida_source=entity)”；parfeval 更像“提交很多任务到后台队列”。

### 3\. `[backgroundPool](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=backgroundPool&zhida_source=entity)`：后台[线程池](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E7%BA%BF%E7%A8%8B%E6%B1%A0&zhida_source=entity)

`backgroundPool` 是 MATLAB 的后台并行环境，可以让代码在后台运行，同时主 MATLAB 会话仍然可用。MathWorks 文档说明，`backgroundPool` 由 thread workers 支持，即使没有 Parallel Computing Toolbox 许可证，也可以使用一个后台线程 worker；有相关工具箱时可以使用更多能力。

典型用法：

```text
f = parfeval(backgroundPool, @longFunction, 1, input);
% 主 MATLAB 还能继续交互、画图或编辑代码
result = fetchOutputs(f);
```

它适合一些后台任务，比如保存大文件、预[处理数据](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%A4%84%E7%90%86%E6%95%B0%E6%8D%AE&zhida_source=entity)、异步加载数据、后台画图、后台计算某个不急需的结果。它不适合需要大量进程级并行的大型数值计算；这种场景通常还是用 `parpool` 配合 `parfor` 或 `parfeval`。

### 4\. spmd：显式多 worker 并行

spmd 的意思是 Single Program Multiple Data。它会让多个 worker 同时执行同一段代码，但每个 worker 可以通过 spmdIndex 或 labindex 知道自己是谁，从而处理不同数据。MathWorks 文档说明，spmd 块内代码会在 parallel pool 的所有 workers 上执行。

示例：

```text
parpool(4)

spmd
    idx = spmdIndex;
    localResult = idx^2;
end
```

spmd 适合比 parfor 更复杂的[并行逻辑](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%B9%B6%E8%A1%8C%E9%80%BB%E8%BE%91&zhida_source=entity)，比如：

```text
每个 worker 维护一份状态
每个 worker 处理一块数据
worker 之间需要通信
需要使用 codistributed / distributed arrays
多 GPU 手动分配
```

spmd 的优点是灵活、强大、可控；缺点是代码复杂度高，需要你显式考虑数据划分、通信、同步和结果汇总。普通[独立循环](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=2&q=%E7%8B%AC%E7%AB%8B%E5%BE%AA%E7%8E%AF&zhida_source=entity)优先用 parfor，只有当 parfor 表达不了你的计算结构时，才考虑 spmd。

| 对比项 | parfor | spmd |
| --- | --- | --- |
| 抽象层次 | 高层 | 低层 |
| 适合任务 | 独立循环 | worker 之间需要协作 |
| [数据通信](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%95%B0%E6%8D%AE%E9%80%9A%E4%BF%A1&zhida_source=entity) | MATLAB 自动处理 | 用户显式控制 |
| 编程难度 | 较低 | 较高 |
| 灵活性 | 中等 | 很高 |
| 分布式数组 | 不是重点 | 非常适合 |
| 多 GPU 控制 | 不灵活 | 更灵活 |

### 5\. 利用[MEX](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=MEX&zhida_source=entity)

MEX 是一种让 MATLAB 调用本地 C/C++/[Fortran](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=Fortran&zhida_source=entity) 代码的[接口机制](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%8E%A5%E5%8F%A3%E6%9C%BA%E5%88%B6&zhida_source=entity)。如果C++ MEX结合[OpenMP](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=OpenMP&zhida_source=entity) / C++ threads / TBB，这就属于CPU 多线程并行。这种并行不依赖 MATLAB 的 `parfor`，而是你的 C++ 代码自己在 MEX 内部开多线程。如果你的 MEX 里调用多线程数学库，比如 BLAS、[LAPACK](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=LAPACK&zhida_source=entity)、MKL、[Eigen](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=Eigen&zhida_source=entity)，那也属于CPU 数值库并行。

## 三、GPU并行

CPU 并行更适合复杂[控制流](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%8E%A7%E5%88%B6%E6%B5%81&zhida_source=entity)、独立任务、分支多、每个任务耗时较长的场景。比如大量独立仿真、有限元计算、多组参数扫描、文件处理、调用外部程序等。 GPU 并行更适合[数据结构](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84&zhida_source=entity)规则、计算密集、同一操作作用在大量元素上的场景。比如大矩阵、[大数组](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%A4%A7%E6%95%B0%E7%BB%84&zhida_source=entity)、图像、[卷积](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%8D%B7%E7%A7%AF&zhida_source=entity)、深度学习、[Monte Carlo](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=Monte+Carlo&zhida_source=entity)、批量函数评价等。 简单说： CPU 多核：擅长“很多复杂任务并行做” GPU：擅长“同一种简单/规则操作对海量数据同时做”。

MathWorks 的示例把 GPU 计算分成三种方式：第一，把输入数据转成 [gpu](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=gpu&zhida_source=entity)Array；第二，对 gpuArray 用 [arrayfun](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=arrayfun&zhida_source=entity)；第三，用 parallel.gpu.[CUDA](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=CUDA&zhida_source=entity)Kernel 运行已有 CUDA/C++ 代码。

### 1\. `gpuArray`：GPU 高层数组并行

`gpuArray` 是 MATLAB 使用 GPU 的核心方式。你不用写 [CUDA kernel](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=CUDA+kernel&zhida_source=entity)，它把数组放到 [GPU 显存](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=GPU+%E6%98%BE%E5%AD%98&zhida_source=entity)中，MATLAB 的重载函数自动调用 GPU 实现。之后支持 GPU 的 MATLAB 函数会直接在 GPU 上运行。MathWorks 文档说明，许多 MATLAB 和工具箱函数在输入为 `gpuArray` 时可以自动在 GPU 上执行，`gpuArray` 表示存储在 GPU 上的数组。

基本形式：

```text
A = gpuArray(rand(5000,5000));
B = gpuArray(rand(5000,5000));

C = A * B;        % 在 GPU 上执行
C_cpu = gather(C); % 拿回 CPU
```

也可以直接创建 GPU [随机数组](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E9%9A%8F%E6%9C%BA%E6%95%B0%E7%BB%84&zhida_source=entity)：

```text
X = gpuArray.randn(1000, 100000, "single");
Y = sum(X.^2, 1);
```

GPU 适合大批量、结构规则、数组密集型计算，比如[大矩阵乘法](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%A4%A7%E7%9F%A9%E9%98%B5%E4%B9%98%E6%B3%95&zhida_source=entity)、卷积、FFT、大规模逐元素运算、深度学习、图像处理、大批量 Monte Carlo 等。

GPU 不适合的场景也很重要：如果数据规模很小，或者每一步都要频繁 `gather` 回 CPU，或者计算中包含大量 GPU 不支持的函数，速度可能不升反降。`gather` 的作用是把 GPU 或 distributed 数据拿回本地 workspace，文档也明确说明 `gather` 会把 `gpuArray` 元素从 GPU 传回本地工作区。

| 对比项 | parfor | gpuArray |
| --- | --- | --- |
| 硬件 | 多核 CPU | NVIDIA GPU |
| [并行粒度](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%B9%B6%E8%A1%8C%E7%B2%92%E5%BA%A6&zhida_source=entity) | 循环迭代级 | [数组元素](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%95%B0%E7%BB%84%E5%85%83%E7%B4%A0&zhida_source=entity)/矩阵运算级 |
| 适合任务 | 独立函数调用、仿真、参数扫描 | 大规模数组计算 |
| 编程方式 | 改 for 为 parfor | 把数据变成 gpuArray |
| 数据限制 | worker 间传输数据 | 受 GPU 显存限制 |
| 开销 | worker 启动和通信 | CPU-GPU 数据传输 |
| 小任务表现 | 可能较差 | 可能较差 |
| 大规则计算 | 不如 GPU | 通常很好 |
| 复杂分支 | 较适合 | 不太适合 |

一个典型误区是：把 parfor 和 GPU 叠加一定更快。单 GPU 情况下，多个 CPU worker 同时抢一张 GPU，往往会变慢。更好的做法通常是：要么 CPU parfor，要么单个 MATLAB 进程把一个大数组送到 GPU 批量算。

### 2\. `arrayfun`、`pagefun`：GPU 元素级/页级并行

除了普通 `gpuArray` 运算，MATLAB 还支持一些更细的 GPU 编程形式。比如 `arrayfun` 可以把元素级函数应用到 GPU 数组上，MathWorks 文档说明 `arrayfun` fully supports GPU arrays，即输入为 `gpuArray` 时可以在 GPU 上运行。

例如：

```text
x = gpuArray.linspace(-5,5,1e7);
y = arrayfun(@(t) sin(t)^2 + cos(t)^2, x);
```

对于很多页矩阵操作，还可以使用类似 page-wise 的批量运算思路，例如对三维数组中每一页做矩阵乘法、矩阵分解或其他批处理操作。它适合“很多个同尺寸小矩阵同时计算”的场景。

这类方式比普通向量化更接近 GPU 的高效使用方式，但也要求函数形式比较规则，不能包含太多 MATLAB 解释器层面的复杂逻辑。

### 3\. CUDA kernel，低层 GPU 编程

前面介绍的是更常用、更高层的 MATLAB 并行方法。MATLAB 确实支持直接运行 CUDA/[PTX](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=PTX&zhida_source=entity) 代码，此时需要主要有两条路：

**（1）parallel.gpu.CUDAKernel**

流程大概是：

```text
k = parallel.gpu.CUDAKernel('myKernel.ptx','myKernel.cu');
k.ThreadBlockSize = [256 1 1];
k.GridSize = [ceil(N/256) 1 1];

out = feval(k, in, out, N);
```

MathWorks 文档说明，可以从 `.cu` 文件编译 PTX，然后用 `parallel.gpu.CUDAKernel` 创建 kernel 对象并运行。这种方式适合你已经有 CUDA kernel，或者 MATLAB 的 `gpuArray` 表达不了你的计算。

**（2）mexcuda**

`mexcuda` 用 NVIDIA `nvcc` 编译 CUDA C++ MEX 文件，允许 MEX 文件定义和启动 [GPU kernels](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=GPU+kernels&zhida_source=entity)，并且可以读写 MATLAB 的 GPU arrays。这种方式更灵活，因为你可以写完整的 C++/CUDA host 代码和 kernel 代码。MathWorks 文档也说，一般来说，MEX 文件比 `CUDAKernel` 对象更灵活。

高层直接用 GPU：`gpuArray`，你不写 CUDA kernel，MATLAB 自动调用 GPU 版本函数。特点是：高层、简单、开发快、依赖 MATLAB 支持的 GPU 函数。低层直接用 GPU：CUDA kernel / CUDA MEX，这是 CUDA 风格，再通过 MATLAB 调用。特点是：底层、灵活、性能可控、开发复杂，需要理解 CUDA 线程、block、grid、显存访问、同步等。简单说，gpuArray 是 MATLAB 帮你写好了 GPU 版本；CUDA kernel 是你自己写 GPU 代码。

| 对比项 | gpuArray | CUDA kernel / CUDA MEX |
| --- | --- | --- |
| 抽象层级 | 高 | 低 |
| 是否写 CUDA | 不需要 | 需要 |
| 开发难度 | 低 | 高 |
| 性能控制 | 较少 | 很强 |
| 调试难度 | 较低 | 较高 |
| 适合任务 | MATLAB 已支持的数组运算 | MATLAB 表达困难或性能不够的特殊计算 |
| [数据对象](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%95%B0%E6%8D%AE%E5%AF%B9%E8%B1%A1&zhida_source=entity) | MATLAB gpuArray | CUDA device memory / MATLAB GPU MEX [API](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=API&zhida_source=entity) |
| 典型入口 | gpuArray, arrayfun | parallel.gpu.CUDAKernel, mexcuda |

## 四、[大数据](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%A4%A7%E6%95%B0%E6%8D%AE&zhida_source=entity)/分布式/集群

一般个人算法开发似乎用不太到？

### 1\. distributed arrays / codistributed arrays：分布式数组

当数组太大，单个 worker 或单机内存放不下，或者你希望多个 worker 共同处理一个大数组时，可以使用 distributed arrays 或 codistributed arrays。MathWorks 文档中把 distributed arrays 作为[并行处理](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%B9%B6%E8%A1%8C%E5%A4%84%E7%90%86&zhida_source=entity)大数据的一类方式，也说明可以在多个 workers 上分布数组。

概念上可以理解为：

```text
普通数组：整个矩阵都在一个 MATLAB 进程里
distributed array：矩阵被切成多块，分布在多个 worker 上
```

适合：超大矩阵、大规模线性代数、数据量超过单机内存、多 worker 协同处理大数组

缺点是编程复杂度更高，很多操作会涉及 worker 间通信。通信开销可能很大，因此只有当数据规模足够大、计算量足够重时才划算。

| 对比项 | gpuArray | distributed arrays |
| --- | --- | --- |
| 目标硬件 | 单 GPU 或多 GPU | 多 CPU workers / 集群 |
| 数据位置 | GPU 显存 | 多个 worker 内存 |
| 主要瓶颈 | GPU 显存、CPU-GPU 传输 | worker 通信、网络/内存 |
| 适合任务 | 大规模规则数值计算 | 超大数组、分布式数据 |
| 编程难度 | 中 | 高 |
| 是否适合小任务 | 不适合 | 不适合 |

gpuArray 解决的是“计算密度高，适合 GPU”；distributed arrays 解决的是“数据太大，要分布存放和计算”。

### 2\. [tall arrays](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=tall+arrays&zhida_source=entity) / [datastore](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=datastore&zhida_source=entity) / [mapreduce](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=mapreduce&zhida_source=entity)：大数据流式并行

`tall arrays` 主要用于数据太大，不能一次性放进内存的情况。它经常和 `datastore` 配合使用，可以分块读取和处理数据。MathWorks 文档把 tall arrays、datastores、mapreduce 归在 Big Data Processing 中，用于并行分析大[数据集](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%95%B0%E6%8D%AE%E9%9B%86&zhida_source=entity)。

典型场景：

```text
ds = datastore("large_folder/*.csv");
T = tall(ds);

summary = gather(mean(T.Var1));
```

`tall arrays` 适合：超大表格、日志数据、大量文件、一次性读不进内存的数据、[数据预处理](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%95%B0%E6%8D%AE%E9%A2%84%E5%A4%84%E7%90%86&zhida_source=entity)和统计分析

它不适合小规模数值优化或实时[迭代计算](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E8%BF%AD%E4%BB%A3%E8%AE%A1%E7%AE%97&zhida_source=entity)。它的优势是处理“数据很大”，不是处理“单次计算很复杂”。

| 对比项 | tall arrays | distributed arrays |
| --- | --- | --- |
| 主要目的 | 处理无法一次读入内存的数据 | 把数组分布到多个 worker 内存 |
| 数据来源 | 文件、datastore、大表格 | 已有大数组或[分布式计算](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%88%86%E5%B8%83%E5%BC%8F%E8%AE%A1%E7%AE%97&zhida_source=entity) |
| 执行方式 | 延迟计算，最后 gather | worker 协同计算 |
| 典型任务 | 大[数据清洗](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%95%B0%E6%8D%AE%E6%B8%85%E6%B4%97&zhida_source=entity)、统计、表格处理 | 大规模矩阵/数组计算 |
| 用户体验 | 类似表格/数组操作 | 更偏并行数值计算 |

tall arrays 更像“[大数据分析](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%A4%A7%E6%95%B0%E6%8D%AE%E5%88%86%E6%9E%90&zhida_source=entity)工具”；distributed arrays 更像“分布式数值计算工具”。

### 3\. `batch`：后台/集群批处理

`batch` 用于把一个 MATLAB 函数提交到后台或集群执行。它适合长时间任务、参数扫描、论文实验、夜间批量运行等。MathWorks Parallel Computing Toolbox 文档中也把 batch processing 作为“把函数执行 offload 到后台”的能力。

示意：

```text
job = batch(@myLongExperiment, 1, {config});
wait(job)
result = fetchOutputs(job);
```

`batch` 的优点是任务可以离开当前交互式 MATLAB 会话运行，适合长任务和集群。缺点是交互性差，不适合每一步都要看结果、调参数的[开发阶段](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%BC%80%E5%8F%91%E9%98%B6%E6%AE%B5&zhida_source=entity)。

### 4\. [MATLAB Parallel Server](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=MATLAB+Parallel+Server&zhida_source=entity) / [Cluster](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=Cluster&zhida_source=entity)：集群并行

如果本机 CPU/GPU 不够，可以把 Parallel Computing Toolbox 的代码扩展到集群或云端。典型是通过 MATLAB Parallel Server 让 `parfor`、`batch`、`spmd` 等运行在多节点环境。Parallel Computing Toolbox 官方页面也说明它可以利用多核桌面、GPU、集群和云资源处理计算密集任务。

适合：大量参数扫描、大规模仿真、多随机种子实验、大型[数据处理](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%95%B0%E6%8D%AE%E5%A4%84%E7%90%86&zhida_source=entity)、多 GPU / 多节点任务

不适合：小规模脚本、频繁交互调试、对延迟非常敏感的任务

集群并行不是“自动更快”，它要考虑数据传输、任务调度、队列等待、[文件系统](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%96%87%E4%BB%B6%E7%B3%BB%E7%BB%9F&zhida_source=entity)等问题。

## 五、横向比较

下面用几个维度来横向比较

### 1\. 按使用难度比较  

| 方式 | 使用难度 | 说明 |
| --- | --- | --- |
| 向量化 | 低到中 | 需要改写代码思路，但不需要并行工具箱 |
| 内置函数自动多线程 | 低 | 基本不用管，写矩阵运算即可 |
| gpuArray | 中 | 要关注 GPU 支持函数、显存、gather |
| parfor | 中 | 循环要满足独立性，[变量分类](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E5%8F%98%E9%87%8F%E5%88%86%E7%B1%BB&zhida_source=entity)要符合规则 |
| parfeval | 中到高 | 要管理 future、异步结果、错误处理 |
| backgroundPool | 中 | 适合后台任务，计算规模通常不宜太大 |
| spmd | 高 | 要自己管理 worker、通信和数据分布 |
| distributed arrays | 高 | 要理解分布式数据和通信成本 |
| tall arrays | 中 | 对大表格友好，但执行模型和普通数组不同 |
| batch / cluster | 中到高 | 要配置集群、任务、路径和[数据依赖](https://zhida.zhihu.com/search?content_id=275432991&content_type=Article&match_order=1&q=%E6%95%B0%E6%8D%AE%E4%BE%9D%E8%B5%96&zhida_source=entity) |

### 2\. 按适用任务类型比较  

| 任务类型 | 推荐方式 |
| --- | --- |
| 普通矩阵运算 | 向量化 + MATLAB 自动多线程 |
| 大矩阵、大数组、深度学习、图像处理 | gpuArray |
| 每个样本独立且很耗时 | parfor |
| 多个实验同时跑 | parfeval 或 batch |
| 后台执行、不阻塞 MATLAB | backgroundPool 或 parfeval |
| 多 worker 需要通信 | spmd |
| 单机内存放不下的大数组 | distributed arrays |
| 超大文件、超大表格、日志数据 | tall arrays + datastore |
| 集群/云端大规模实验 | batch + MATLAB Parallel Server |

### 3\. 按开销比较  

| 方式 | 主要开销 | 什么时候不划算 |
| --- | --- | --- |
| 向量化 | 改写代码成本 | 逻辑过于复杂时不易写 |
| 自动多线程 | 几乎无显式开销 | 代码不是内置矩阵运算时帮助有限 |
| gpuArray | CPU-GPU 数据传输、GPU 启动、显存 | 数据太小、频繁 gather、函数不支持 GPU |
| parfor | 启动 worker、分发数据、汇总结果 | 单次循环太快、数据传输很大 |
| parfeval | future 管理、任务调度 | 任务太小或强同步 |
| backgroundPool | 后台线程调度 | 需要重计算密集多进程时不够 |
| spmd | 通信和同步 | 不需要 worker 通信的普通循环 |
| distributed arrays | worker 间通信 | 数据不够大或通信多于计算 |
| tall arrays | 分块读写、延迟求值 | 数据能轻松放进内存时 |
| batch / cluster | 队列、路径、文件传输 | 小任务、交互式调试 |

### 4\. 按加速潜力比较  

| 方式 | 加速潜力 | 说明 |
| --- | --- | --- |
| 向量化 | 高 | 很多 MATLAB 代码最大收益来自这里 |
| 自动多线程 | 中到高 | 取决于是否调用高性能内置函数 |
| gpuArray | 很高 | 对大规模规则数组计算非常强 |
| parfor | 中到高 | 对独立重任务很好，对轻任务一般 |
| parfeval | 中到高 | 适合任务级并行，不一定提升单任务速度 |
| backgroundPool | 低到中 | 更偏异步，不是极限性能工具 |
| spmd | 很高 | 适合复杂分布式或多 GPU，但编程成本高 |
| distributed arrays | 很高 | 数据足够大时可突破单机限制 |
| tall arrays | 中到高 | 面向大数据处理，不是低延迟计算 |
| cluster / batch | 很高 | 适合大规模实验，但依赖硬件和调度系统 |

### 5\. 如何选择：一个实用决策表  

| 你的问题 | 优先选择 |
| --- | --- |
| 代码里很多普通 for 循环，但每次循环很快 | 先向量化 |
| 代码主要是矩阵乘法、分解、FFT | 先用内置函数，不一定需要显式并行 |
| 每次循环独立，而且每次很耗时 | parfor |
| 想同时提交多个实验，哪个先算完先处理哪个 | parfeval |
| 想后台运行，不阻塞 MATLAB | backgroundPool 或 parfeval |
| 大数组规则运算，GPU 支持 | gpuArray |
| 一个数组太大，单机内存不够 | distributed arrays |
| 数据文件太大，不能一次读入 | tall arrays + datastore |
| 需要 worker 间通信或手动分块 | spmd |
| 要跑几百组长实验 | batch / cluster |
